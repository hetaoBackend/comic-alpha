# ComicBrain Agent 规则

ComicBrain 是面向多系列漫画创作的持久 Wiki。不要把本文件当成完整操作手册；按任务调用下面两个技能。

## 必须调用的技能

- **Wiki 使用与写回**：凡涉及系列、人物、世界观、剧情、脚本、分镜、连续性、正史、证据或 production 导出，必须完整读取并使用 `.agents/skills/comic-wiki/SKILL.md`。
- **用户反馈与偏好学习**：凡用户认可、否决、纠正或要求修改人物、剧情、对白、节奏、分镜、画面或协作方式，必须额外完整读取并使用 `.agents/skills/comic-feedback/SKILL.md`。
- 两者同时触发时，先由 `comic-feedback` 区分症状、目标、修法和可泛化偏好，再由 `comic-wiki` 负责证据写入、当前知识同步与校验。

## 精简后的工作空间

- `wiki/`：创作者和 Agent 的唯一知识入口。系列正史、创作原则、创作偏好、系列提案和追加式证据都在这里。
- `wiki/证据/`：只保存决策、反馈和外部来源的追溯记录；默认不作为当前正史读取，旧记录不改写。
- `.agents/skills/`：Agent 的操作规则、校验脚本和新建系列所需资源。
- `production/`：从 Wiki 编译给漫画制作工具的派生结果；`storyboard.json`、`review.json` 和生成图片不得自动回写正史。
- 每章创建或实质改写 `01-漫画脚本.md` 时，同步维护同目录 `04-封面描述.md`；封面描述由 Wiki 导出到 production，不从正文首格临时拼接。
- 生成或实质改写剧情、脚本、分镜、人物设定或人物视觉前，必须按 `comic-wiki/references/creation-rule-protocol.md` 扫描全部当前有效全局原则、全局偏好与目标系列偏好；适用项必须进入设计，不适用或被覆盖项必须说明原因。

讨论中的想法默认留在对话；需要持久化时写入目标系列的 `提案/` 并标为 `draft`。旧正史原位标为 `deprecated` 并指向替代决策，不另建全局 archive。

## 权限与专业判断

1. 用户对阅读感受拥有第一手权威，对审美方向和正史取舍拥有最终决定权。
2. 用户提出的原因或修法不自动正确。Agent 必须检查因果、人物动机、连续性、媒介限制、信息负担和下游影响。
3. 若症状成立但修法会制造新问题，明确说明冲突并给出更小、更连贯的替代方案；不得为迎合而记录错误事实或错误诊断。
4. 用户了解代价后仍明确选择，可按局部决定或例外写回；除非用户明确泛化，不得升级成全局偏好。

## 不可违反的写回规则

1. 讨论、猜测和候选方案不得写成 `canonical`。
2. 只有用户明确确认或直接命令修改 Wiki，才更新正史。
3. 确认写回前检查相关人物、关系、时间线、世界规则、最近剧情和适用创作原则。
4. 先向 `wiki/证据/剧情决策日志.md` 追加决策，再同步主要产物和下游状态。
5. 用户反馈先由 `comic-feedback` 分类；偏好必须附证据、范围、状态、置信度和反例条件。
6. 不删除旧证据，不静默覆盖冲突，不从 production 或生成图反推正史。
7. 人物形象放在对应系列的 `assets/人物/<人物ID>/`，人物档案只引用真实存在或明确标注待生成的资产。
8. 新建或实质改写章节/人物时，分别在章节卡或人物档案写入 `rule_context: reviewed` 与“规则应用记录”；没有实际复审不得补写标记。

从根目录 `index.md` 开始导航。
