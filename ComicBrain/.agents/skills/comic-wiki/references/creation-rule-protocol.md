# ComicBrain 创作规则预检协议

剧情、章节、脚本、分镜、人物设定或人物视觉任务开始前，完整读取本协议。目标是保证 Wiki 中当前有效的原则与偏好都进入判断，不是把所有规则机械套在每一种任务上。

## 1. 建立完整规则目录

从以下入口发现规则，不凭记忆列举：

1. `wiki/创作原则/index.md` 以及它链接的每一份当前有效原则/门禁页；
2. `wiki/创作偏好/index.md` 以及它链接的每一份全局偏好页；
3. 目标系列 `05-系列偏好.md`；
4. 目标系列 `01-创作约束.md` 中“对全局原则的有意覆盖”。

完整读取所有当前有效原则页。完整读取所有偏好页；逐条检查 `stable` 与 `candidate`，读取 `rejected` 只为防止重新误用。不得因为某条规则是本次任务之后新增的，或不在 Agent 记忆中，而跳过目录扫描。

## 2. 逐项判定，不静默遗漏

对每份原则和每条偏好选择一种状态：

- **采用**：与任务相关，必须转化为至少一个具体设计决定或验收动作；
- **不适用**：与当前任务对象、类型、媒介阶段无关，写出一句具体原因；
- **覆盖**：被更窄的系列约束、系列偏好、人物规则或用户本轮明确指令替代，指出覆盖来源；
- **禁止误用**：状态为 `rejected`，只记录其不能作为当前依据。

优先级固定为：

`用户本轮明确指令 > 系列创作约束 > 已确认正史与人物逻辑 > 系列偏好 > 全局稳定偏好 > 全局原则 > candidate 偏好 > Agent 临时建议`

`candidate` 只能作为需要验证的假设，不得伪装成强制要求。若两条规则冲突，采用更窄、更明确、更新且有证据的一条，并记录另一条为何不执行。

## 3. 不同任务的最低深度

全量扫描始终执行；以下只是不得低于的深入应用集合。

### 剧情、章节、脚本与分镜

- 深入使用：故事与主题、角色与关系、漫画脚本、分镜与节奏、视觉连续性、剧情质量门禁、叙事简洁与信息负担。
- 喜剧、校园/生活单元、快读开篇：必须深入使用“情景喜剧、百秒钩子与冲突引擎”。
- 新增或实质改变人物造型：同时深入使用“人物视觉设计”。
- 涉及外部资料或标杆学习：同时使用“来源与技能调研”。

### 人物设定与人物视觉

- 深入使用：故事与主题、角色与关系、人物视觉设计、叙事简洁与信息负担、剧情质量门禁中的人物/媒介项。
- 喜剧群像人物：必须深入使用“情景喜剧、百秒钩子与冲突引擎”中的群像接口、错位与反应功能。
- 同组人物视觉：必须应用全局视觉偏好和系列视觉约束，完成剪影、体量、大色块、动作轴及同框差异检查。
- 角色不是孤立立绘：人物档案必须说明欲望、压力策略、关系触发器、可表演动作与在故事中的可碰撞接口。

## 4. 把规则变成设计决定

禁止只写“遵循原则 01、02、11”。每个采用项至少回答：

- 这条规则改变了哪个选择、冲突、动作、造型或验收？
- 如果不采用，产物会出现什么具体风险？
- 最终在哪个章节节拍、人物字段、分镜格或视觉锚点中可以看到它？

规则应用记录使用：

```markdown
## 规则应用记录

- 规则目录检查：已完整读取全局原则、全局偏好、系列偏好与系列覆盖
- 审阅日期：YYYY-MM-DD

### 已采用

| 规则/偏好 | 本次具体应用 | 可见位置或验收 |
|---|---|---|

### 不适用、覆盖与禁止误用

| 规则/偏好 | 状态 | 原因或覆盖来源 |
|---|---|---|
```

持久化章节内容时，把记录放在 `00-章节卡.md`，删除骨架专用的 `creation_stage: skeleton`，并在其 frontmatter 写 `rule_context: reviewed`。创建或实质改写 `01-漫画脚本.md` 时，同样删除脚本的骨架标记，并同步更新章节卡的日期与规则记录。

持久化人物内容时，把记录放在人物档案，删除任何骨架标记，并在 frontmatter 写 `rule_context: reviewed`。只更新图片文件、不改变人物设计时，可在资产登记中保留原审阅来源，无需重写人物档案。

讨论阶段没有写文件时，在回复中给出精简版“本轮采用 / 主要不适用或覆盖”，不能省略规则扫描。

## 5. 完成前复核

提交前确认：

1. 原则目录中的每个当前有效页面都已被判定；
2. 全局和系列偏好中的每条 `stable`/`candidate` 都已被判定；
3. 所有“采用”项都能在产物中找到具体证据；
4. 所有“不适用/覆盖”都有任务相关原因，而不是“没想到”；
5. 没有用全局偏好覆盖更窄的系列规则；
6. 没有把偏好写成剧情事实；
7. 章节或人物持久化产物已留下 `rule_context: reviewed` 与“规则应用记录”；
8. 已运行 `check_wiki.py`，且规则记录校验通过。
