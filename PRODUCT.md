# ComicPerfect

Local comic creation console for a creator working with a private ComicBrain Wiki.
Two paths: continue a series using its principles and story memory, or create a standalone comic from an idea. Creators edit story drafts before generating storyboards and images. Series and completed comics remain browsable with their history.

Specific-source planning discovers a concrete source scene before writing the new episode. A bounded automatic repair handles malformed model output; the UI never asks the creator to fill internal attribution fields. Optional 亮点剧情 discovery searches public sources using only the reference work and explicit keywords, labels search snippets and model memory as unverified, and exposes only actual returned source links. Creators can add, reorder and remove scenes in a saved 系列脉络. These are future adaptation plans, never events already established in the series. 设计剧情 shows the series' planned scenes and offers 按脉络顺序, 我来选 (one picked scene per chapter, in click order) or AI 自动选段; free text that clearly names a planned scene selects it. Queue mode uses the first unconsumed selected scenes, revision keeps the source, and new scenes are discovered when the queue is empty or exhausted.

Every planned chapter is written as 起承转合 with a conflict engine (desire, obstacle, the choice that blocks retreat, what the escalation changes, who turns the tables and how, the payoff) and, when adapting, a beat map to the source scene whose reversal must land on 转. A writer pass drafts the story alone; a separate review pass applies every creative rule and flags a missing reversal, flat escalation, moralising ending, unfaithful adaptation or out-of-character action; one repair pass addresses flagged chapters. A draft that cannot be repaired is kept with its issues shown. Revising keeps the source scene and re-checks all four beats. Drafts saved with the older three-beat shape stay editable. Only a confirmed chapter save consumes a scene; deleted chapter source IDs remain skipped without retaining the deleted story. Source metadata comes from discovery or the saved plan; the writer supplies its new story and adaptation. Manual discovery requests 10 distinct short, self-contained everyday scenes, rather than whole-episode arcs or isolated catchphrases. It expands official episode metadata when available, screens for compact visual situations, and replenishes rejected or duplicate candidates in bounded passes; a genuine shortage is explicit. Candidate previews and the selected storyline stay concise, with full provenance available on demand and existing saved source details preserved.

Drafts, individual chapters and whole series support permanent deletion. Preparation computes the file and continuity impact before a named, irreversible confirmation. Chapter deletion reconciles current state, story spine, timeline, character/world notes and learned chapter rules against surviving chapters; an incomplete cleanup blocks deletion. Commit purges owned work, exclusive generated images, undo/proposal/history copies and browser caches, retaining images shared with surviving work. Opaque deleted IDs prevent stale tabs and in-flight writes from restoring content. Multi-chapter drafts keep their unaffected chapters. No deletion occurs on discussion or cancel.

系列长期参考 is set once during series creation or edited under the series 参考与脉络 tab. It stores a work, reference mode (tone/interaction only or a specific source plot for every episode), and borrowing priorities in that series' preferences. The first draft uses it immediately; saving the first chapter persists it with the new series. Every later planning request reads the current series setting from disk. 本话临时参考 overrides only that planning request, never the saved default. Plot mode requires concrete source-scene attribution, marked unverified when based on model memory; source selection remains visible and is retained in chapter memory.

The creator has superseded the old comicperfect-ux.html visual reference and chosen a creation-software interaction: navigation left, authored work in the center, contextual tools and assistant on the right. The current studio implementation is the visual authority. Preserve Codex, Gemini and OpenAI-compatible generation, style references, covers, exports and social copy. Private Wiki content is available only through localhost APIs; the supported static server must never expose the repository. Production drafts and images are not canon. Clicking 保存本话到系列 explicitly authorizes one direct save with continuity checks, evidence and conflict detection. Final authored panels and covers are serialized by code; AI extracts a compact summary and affected state changes, generates or updates a concise retrospective when needed, and evaluates edits against the AI original. No second confirmation. Local choices stay local; quality lessons become scoped candidates. Explicit future guidance can update series creative requirements after professional judgment. Never promote one local edit into a global rule. Preserve manually edited retrospectives and offer independent adjustment.

User-facing language treats the workspace as one product. Use 创作原则 and 创作记忆; do not expose the ComicBrain name, internal Wiki/production storage terms, or split-product responsibility taglines in navigation, help, settings, status or confirmation copy. Internal integrations and stored identifiers remain compatible.

The contextual 创作助手 uses the configured text provider, including Codex, for multi-turn discussion and scoped writing edits. It is available globally and beside story, page, cover and creative-document content. Always name the selected target and whether changes affect this draft, one series or all series. Discussion does not mutate content. Concrete edits show before/after previews before adoption; draft edits preserve generated image history and support conflict-aware undo. Document adoption preserves identity and status, records evidence, and validates a staged workspace before updating current files. Never infer a permanent preference from one local change. History and unsent instructions are scoped to the workspace and target. Cover, publishing and export actions remain discoverable in the output stage.

创作空间 is a visible sidebar destination showing the current folder, recent spaces, open-existing and create-empty actions. Desktop folder selection is native and trusted; switching waits for pending saves, then relaunches into the target. Startup-configured roots are explicitly locked. Creating a space copies reusable behavior and an empty Wiki only, never another creator's canon, assets or production. Browser-only use explains that the running service selects its workspace. ComicPerfect's product mark combines comic panels with a speech bubble; interface, favicon and macOS icon share the asset under assets/brand.

Workspaces belong to the user filesystem. First launch opens or creates a named folder; subsequent launches reopen the last selected folder. A portable comicperfect.workspace.json stores stable identity and relative images; app preferences hold only location and shell state. Moving a folder must preserve draft cache identity. Creation data is never silently recreated in app storage when a selected folder is missing.
